# 最小可交付工程计划 (Minimal Deliverable Plan)

## 1. 风险控制 (Risk Control) - `policy_rules.json`
**目标**: 简单粗暴的 Denylist，防止 Agent 越界。
- **文件定义**: 在项目根目录定义 `policy_rules.json`，包含 `blocked_paths` (如 `.env`, `secrets/`) 和 `blocked_commands` (如 `rm -rf`, `curl | sh`)。
- **实施**:
    - 修改 `director_exec.py`，在执行任何工具命令前加载规则。
    - 命中规则时：
        1. 阻止执行。
        2. 抛出 `POLICY_BLOCKED` 错误码。
        3. 自动生成一个 `Intervention` (类型: `policy_block`)，与我们刚做好的 Intervention Center 闭环。

## 2. 观测基准 (Metrics) - `metrics.json`
**目标**: 用少而准的数据替代主观臆测。
- **文件定义**: 每次 Director 运行结束时，在 `runs/<run_id>/` 下生成 `metrics.json`。
- **指标**: 严格限制为以下字段：
    - `status`, `failure_code`
    - `iterations` (修复轮次)
    - `tool_calls` (工具调用次数)
    - `duration_ms`
    - `files_changed_count`, `lines_added`, `lines_removed`
    - `risk_score` (已有逻辑)
    - `qa_pass` (QA 是否通过)
- **实施**: 修改 `loop-director.py` 和 `director_trajectory.py`，在运行结算阶段输出此文件。

## 3. 恢复能力 (Resume) - `checkpoint.json`
**目标**: 失败不崩盘，从断点续跑。
- **文件定义**: `state/ollama/checkpoint.json`。
- **内容**: `{"phase": "pm|director", "pm_iteration": N, "step": "...", "last_seq": N, "run_id": "..."}`。
- **实施**:
    - `loop-pm.py`: 每完成一个关键步骤（Loop Start, Director Start, Review Start）就原子写入一次 Checkpoint。
    - 增强 `--resume` 逻辑：启动时优先读取 `checkpoint.json` 恢复状态，而不是仅仅依赖 `PM_STATE.json` 的粗粒度计数。

## 4. 确定性 UI (UI Events) - `ui_events.jsonl`
**目标**: UI 渲染不再靠“猜日志”。
- **文件定义**: `state/ollama/ui_events.jsonl` (流式)。
- **内容**: 仅包含明确的 UI 卡片事件，如 `{"type": "card", "kind": "tool", "content": "..."}`, `{"type": "card", "kind": "summary", ...}`。
- **实施**:
    - 后端：在 `io_utils.py` 中增加 `emit_ui_event` 函数，并在关键节点调用。
    - 前端：Dashboard 监听此文件（或通过 WebSocket 转发），逐步替代现有的 `CodexCliStreamParser` 猜测逻辑（旧逻辑降级为 fallback）。
